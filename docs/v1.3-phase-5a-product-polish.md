# V1.3 Phase 5A: product polish and integration review

Reviewed on 2026-10-13 on `feature/v1.3-balanced`, starting at
`c154b94c496db9c55342e91a8d9b01faa6fc69b7`. The tracked tree was clean;
all six unrelated untracked reports/investigation files were preserved.
A read-only GitHub Releases API check confirmed `v1.2.0-rc.1` remains the
latest published release, marked as a prerelease.

## Confirmed corrections

- WorkSession reminders previously required the Calendar context menu. Ordinary
  clicks select the Task, and the WorkSession had no focusable menu control.
  A small, named menu button now provides pointer and keyboard access to the
  existing reminder/completion/removal actions. It stops drag/click propagation,
  sits above the existing drag overlay, and is absent from drag previews.
- Event and WorkSession reminder controls now explain that preferences stay on
  this device, notifications require permission, and Planstrand must be running.
  The Event selector associates the explanation with `aria-describedby`.
  Existing translation fallback supplies the new English text for other locales.

The changes reuse Blue Thread colors, surfaces, spacing, typography and menus.
No planning semantics, shared entity fields, persistence schemas, reminder
scheduling rules, Calendar renderer or navigation were changed.

## Reviewed behavior

Quick planning retains Today, Tomorrow, This Week, Next Week and Unplan inside
the expandable Task actions. Tests exercise Tasks, Today and This Week, pointer
and keyboard selection, offline use, year/week boundaries and a UTC+14 browser.
Task records (including deadlines) and WorkSessions remain identical when only
Planning placement changes. Focused unit coverage also exercises midnight and
configured week-start boundaries.

Reminders retain all seven existing choices: Never (Off), when it starts, and
5/10/15/30/60 minutes before. Local preferences survive reload/restart using the
same profile. The scheduler derives current starts on each tick; removed entities,
completed WorkSessions and all-day Events cannot deliver. Existing tests cover
movement, stale asynchronous permission waits, import/global-disable gates,
deduplication and unchanged Task reminder fields. Recurring Events remain excluded.

Update discovery retains RC/stable channel selection, explicit dismissal,
quiet automatic offline failures and the official GitHub Releases link.
`UPDATE_PUBLIC_KEYS` remains empty: production authenticated downloads are disabled
and discovery cannot advertise them. The UI contains no installation or restart
action; update IPC exposes discovery, download and status only. Registration and
staged-file validation foundations remain intact. No installer investigation or
Windows-native probe was executed.

Existing README/manual-upgrade guidance and Phase 2/3A/3B/4 help documents were
reviewed. Verified application-data checkpoints are JSON model exports, not
complete-profile backups, automatic rollback or independent disaster-recovery
copies. Device-local schedule reminder preferences are outside those model exports
and sync. Upgrades continue to require an independent backup and manual download
and installation. The README remains focused on the published V1.2 release;
no release notes were prepared.

cache-enabled host builds exited without diagnostics. No repository build settings
or security settings were changed. Sandbox localhost/hard-link restrictions were
handled by running the affected checks on the host.

## Remaining release boundaries

Production authenticated downloads still require an owner-approved, provisioned
Ed25519 trust identity and signed metadata. Fully assisted installation remains
unsupported and disabled in V1.3. This review does not establish Windows signing
or packaged upgrade/installation readiness. No new installer mechanism, signing
key, public version, tag, workflow, release asset or publication was introduced.
All tests use isolated browser contexts or disposable fixtures; existing user
profiles and historical releases are untouched. Nothing was pushed or merged.
