# Planstrand V1

Primary navigation includes Inbox, Master Tasks, Today, This Week, and Calendar.
Folders appear below these destinations. More contains Projects, Tags, Boards,
the upstream Planner, Habits, plugins, and other inherited tools. More opens
automatically on legacy work pages. Search, Help, and Settings remain easy to reach.
Legacy Tasks and Legacy Capture retain the upstream work-context views and their
context menus. Calendar is always reachable from primary navigation; new installs
enable it by default. Saved feature settings and routes are retained.

New installs start on Today (`/today`). Settings offers the primary Planstrand
startup pages. Previously saved numeric destinations and Project IDs keep their
existing meaning, including legacy Today. Missing, archived, or hidden startup
Projects, disabled legacy destinations, and invalid values fall back to `/today`.
An unavailable Folder page links back to Master Tasks without removing any Tasks.

Master Tasks displays Inbox and all Folders, including empty and nested Folders.
Add Task captures directly into its Folder. The shared add-task bar also defaults
to the Folder being browsed; other primary pages capture into Inbox.
Folder controls create, rename, reparent, reorder, and delete leaf Folders.
Deleting a Folder keeps its Tasks, whose effective ownership becomes Inbox.
Expand/collapse is stored only on this device.

Move Task to Folder opens a destination picker. Dragging a Task to another Folder's
Task list performs the same move. Subtasks follow their top-level Task. Drag a Folder
heading onto another Folder heading to reparent it, or onto the root drop area to
make it a root. Move controls provide keyboard alternatives.

Search covers all Tasks and shows the effective ancestor Folder path. Today and
This Week use independent Planning membership. Use Plan Task to choose Today,
another day this week, week-level placement, or Unplan. Drag between Planning
sections or use the up/down controls to move and order Tasks. Unplan removes only
Planning membership; it does not delete the Task or remove scheduled sessions.

Calendar and each Task's Schedule WorkSession command use WorkSessions. A planned
Task need not have a timed session, and a scheduled Task need not be planned.

Calendar shows WorkSessions, local Events, and existing external calendar
sources in Day, Week, and Month. New Event opens a small title/date/time/timezone
editor; the empty time-area placeholder also offers New Event. Click a local Event
to edit it or permanently delete it after confirmation. Timed Events can be moved
and resized in the Day/Week grid. All-day Events appear in the day header and Month
on their stored date, which does not shift with timezone changes. Events are
independent of Tasks and WorkSessions and work offline using the same local store,
backup, and sync pipeline. External events retain their provider behavior.

The Event editor uses the configured or system timezone. When the browser cannot
provide a system timezone, it offers an editable UTC default. Invalid explicitly
configured timezones still require correction. Empty task lists and planning
sections provide short guidance; Add Task, Create Folder, Plan Task, and New Event
are the first-use actions. Folder move/reorder controls provide non-drag alternatives.

## Shipped V1 scope

V1 includes Folder hierarchy, Inbox, Master Tasks, Today, This Week, independent
Planning, WorkSessions, local timed/all-day Events, and Day/Week/Month Calendar.
Tasks retain existing recurrence and reminders. Local-first persistence, sync,
backups, and external calendar display/integration use the inherited infrastructure.
Existing Projects, Tags, archive, Boards, issue integrations, plugins, focus and
time tracking remain available.

Web/PWA, Electron desktop (Windows, macOS, Linux), and Capacitor Android/iOS
foundations are inherited. Primary layouts support desktop, tablet and phone
widths. Native distribution/signing and provider-specific permissions still use
the existing platform release processes; browser checks do not replace native
device certification.

## Post-V1 scope

Local Events are single occurrences. Advanced Event recurrence, WeeklyTemplate,
normalized Event/WorkSession reminders, Trash, new E2EE recovery architecture,
encrypted backup redesign, advanced provider Event export, Year view, exhaustive
UI polish, and other advanced roadmap items are deferred. They do not block V1.

## Release metadata

The primary display identity is Planstrand, including browser/PWA titles, Settings,
desktop window/menu labels and native launcher display names. The technical
version remains the upstream `19.1.0` build version; V1 describes Planstrand's
product scope rather than a downgrade of that version sequence.

Package/application IDs, database/storage keys, migrations, protocol names, OAuth
identities, signing identities, artifact filenames, update endpoints and store
overrides remain upstream-compatible. Upstream changelog and community/support
links are attribution or inherited services, not a Planstrand release channel.
Before publishing, establish Planstrand's release channel, signing/store ownership,
and release version through the existing release process. No release is published
by Milestone C.
