# V1.3 reminder delivery investigation

Baseline verified: `feature/v1.3-balanced` at
`ef8ba2f19d5b46aaee183af7bb7648b20e6556fa`, public `1.3.0-rc.1`, technical
`19.1.0`. Existing untracked files, builds and profiles were preserved.

## Root cause

`LocalScheduleReminderService.checkDue` passed
`planstrand:<kind>:<entity-id>:<remindAt>` to `NotifyService.notifyDesktop`.
`NotifyService.notify` uses the renderer Notification constructor in Electron,
including development mode. Electron 43.5.0 passes Chromium's notification ID
(`n#<origin>#<tag>`) to the Windows toast Tag property. With a normal Event ID,
the combined value exceeds the native limit. The native diagnostic reproduced:

`WinAPI: Setting tag failed, ERROR Notification failed - The size of the
notification tag is too large. (HRESULT: -2143420138)`

Both Events and WorkSessions use this path. A direct renderer test without a
tag works, so it cannot validate the original reminder options. In one disposable
Electron profile, direct/icon/data/short-tag probes emitted `show`; the original
long-tag probe did not. This establishes an application option defect rather than
a development registration failure. Electron's implementation is visible in
[WindowsToastNotification::CreateToastNotification](https://github.com/electron/electron/blob/v43.5.0/shell/browser/notifications/win/windows_toast_notification.cc).

## Trace and fix

- `DialogEventComponent.save` stores numeric `0` for “when it starts” using the
  newly created or existing Event ID. Reopening reads `offset` from localStorage.
- `_editedInstant` / `zonedDateTimeToTimestamp` resolve IANA wall times. October
  13, 2026 at 23:15 / 23:35 in America/Vancouver is October 14 at 06:15 / 06:35
  UTC (`1791958500000` / `1791959700000`). UTC date rollover is expected. The
  provided second screenshot has no clock, so it alone cannot establish lateness.
- `ReminderModule` initializes `ReminderService` at bootstrap. Its module worker
  emits local ticks every ten seconds even with no Task reminders.
- `LocalScheduleReminderService.init` waits for hydration and selects live Event,
  WorkSession and Task signals. `_current` subtracts the offset from the current
  start. `checkDue` pauses during import/global disable, rejects deleted/all-day
  Events and completed/orphaned sessions, and allows a two-minute overdue grace.
- Electron sets `backgroundThrottling: false`; there is no visibility/focus gate
  in this reminder path. Suspension can still exceed the grace.
- Electron development and packaged mode use basic renderer notifications.
  Production/staging browsers can use service-worker notifications. This fix
  removes the optional OS replacement tag from local schedule reminders only.
- Persisting consumption before delivery explains why a rejected toast is not
  retried. Task reminder dismissal cooldowns are separate. Full entity/instant
  keys remain in localStorage; no deduplication, defaults or schemas changed.

The smallest fix removes the redundant notification tag. Two regression tests
assert untagged Event/WorkSession delivery with durable restart deduplication.
The three focused Jasmine files pass **47 tests**; notification delivery is mocked
in those tests. A separate Electron development probe uses the real Windows API
and observes native `show` events for both fixed Vancouver Event instants and a
WorkSession. The first Event goes through the editor; the second Event and the
WorkSession use application commands/state in that disposable profile. The probe controls only its
renderer clock, uses a new disposable profile and local port, and runs the real
worker; it does not change the system clock. Native `show` evidence is distinct
from a human visually confirming the toast.

## Minimal manual verification

1. Start `npm run startFrontend`. In a second terminal run
   `npm start -- --user-data-dir="<new absolute disposable profile path>"`.
2. Ensure Disable all reminders is off. Create a standalone timed Event a few
   minutes ahead in America/Vancouver, with a valid later end and “when it starts”.
   Reopen it to confirm the selected reminder persists.
3. Keep Electron running past the start. Allow ten seconds for the next tick;
   verify the Windows toast. Repeat with the window minimized and a WorkSession
   reminder. Reload afterward and confirm the same instant does not replay.
4. Use a new Event or a new start instant for retries: an already consumed instant
   intentionally stays consumed. Do not clear a real profile or change security.

Windows permissions, notification suppression and development app identity can
still prevent display. [Electron documents development registration requirements](https://www.electronjs.org/docs/latest/tutorial/notifications).
No registration changes, security changes, packaging, installer probes or cloud
services were used. Closed-app alarms remain outside this best-effort feature.
