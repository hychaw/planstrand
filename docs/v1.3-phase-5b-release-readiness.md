## Decision and approval boundary

**READY WITH DOCUMENTED NON-BLOCKING LIMITATIONS**.

Application behavior, packaged unpacked/Portable startup and persistence, and a
real published-V1.2 profile upgrade with complete-model restore are verified.
Production authenticated downloading and assisted installation are deliberately
disabled/deferred. The NSIS package builds and passes metadata/ownership contracts,
but installer execution requires a suitable disposable Windows environment and
was not tested on this host. Actual native OS notification popups, delivery during
sleep/closed-app conditions, full-filesystem recovery, other platforms and a hosted
sync deployment are not certified by this validation. No Norton block occurred
in the final Node packaging/smoke checks. These boundaries must remain explicit
in approval; unit results are not substituted for missing installer or OS checks.

Do not publish these local artifacts automatically. Required owner actions are:

1. Review the final source, evidence and explicit limitations. Run Setup
   install/upgrade/uninstall smoke in a disposable Windows environment before
   publication, or explicitly accept that remaining validation limitation.
2. Approve the exact release revision and authorize pushing it and creating
   `v1.3.0-rc.1`. This preparation grants no push/tag permission.
3. Authorize the manual release workflow with that exact 40-character `ref`,
   matching `release_tag`, and optional `create_draft=true`. The local artifacts
   were built at `6084386fe644e843e6080a67930d94624dc0f1ee`; the subsequent
   evidence/smoke-script commit changes no packaged runtime. If that later revision
   is approved, rebuild through the workflow so provenance matches the approved SHA.
4. Review resulting checks, manifest and draft assets, then separately approve
   publication. Switch README download links only at publication. Preserve all
   V1.0/V1.1/V1.2 releases, tags and assets.

Nothing was pushed, tagged, merged, uploaded or published; no workflow was
