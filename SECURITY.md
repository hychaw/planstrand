# Planstrand Security Policy

## Supported versions

Security fixes currently target the public `v1.0.0-rc` line, beginning with `v1.0.0-rc.1`. Earlier inherited versions and development snapshots have no separate support commitment. Use the latest public RC and keep independent backups.

## Reporting a vulnerability

Please do not disclose an exploitable vulnerability in a public issue, pull request, or discussion before coordinating a fix.

If GitHub Private Vulnerability Reporting is enabled, use **Security → Advisories → Report a vulnerability** in the [Planstrand repository](https://github.com/hychaw/planstrand/security). Include affected versions/platforms, reproduction steps, potential impact, and a minimal example without real user data or credentials.

If that button is unavailable, ask `@hychaw` in a public issue to enable private vulnerability reporting or arrange a private reporting route. Include no exploit details or sensitive information in that request. No dedicated private email address is currently published.

## Scope

Reports may cover the desktop application, locally built web application, backup/import handling, integrations, and included sync-client/server components where applicable. Third-party services have their own reporting policies. Planstrand does not operate a public sync service or promise a response deadline. Maintainers will coordinate assessment, fixes, and disclosure as resources allow.
